## 1. V1-M1-003B：显式奖励、消费与冲正

- 主 actor 的 RewardLedgerService 是唯一业务写入口；领域值与键独立于 View。XP 有效总额与 Coin 余额只由交易派生，不另存可漂移余额或等级，不设未确认默认。
- 来源使用完成/购买事件稳定 UUID，不能用会重复完成的实例 ID。收入 XP/Coin 成对写入，零奖励也保存事件键；同来源相同金额重试返回原写入时间、不新增，同来源改变金额明确拒绝。重试传入的当前时间不改写原事实。
- 消费成本必须为正，余额不足拒绝；冲正关联原收入并精确反向，重复冲正不重扣，币不足时 XP、收入、消费与状态均不改。纠错后的有效 XP 是后续等级重算输入，普通未完成不扣分。
- 读取验证规范键、类型/符号、成对收入/冲正、准确反向金额、时间与非负总额；损坏不能静默忽略。异号抵消再累加，避免 fetch 顺序产生假溢出；真实 Int 溢出抛明确错误。
- 独立保存要求 context 干净，临时关闭自动保存，所有校验到保存同步执行；失败回滚该事务且恢复设置，不保存或丢弃用户未提交编辑。保存边界的抛错替身覆盖收入/消费/冲正；真实磁盘成功路径另行验证。
- `stage` 入口只暂存，供后续完成/宠物事件与账本统一保存。调用方必须拥有外层关闭自动保存、保存与回滚边界；暂存结果不是到账收据。组合根应保持同家庭库单一写上下文，不支持多个未保存上下文竞争写账；尚未接入 App 完成 UI。
