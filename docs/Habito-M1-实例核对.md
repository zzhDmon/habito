# Habito M1 实例幂等核对

## 1. 服务职责

`TaskOccurrenceReconciliationService` 把已经完成规则展开和覆盖合并的候选写入 SwiftData。服务一次只处理一个模板和一个明确的闭合日期范围，不读取系统当前日期或时间。

## 2. 更新矩阵

| 已有实例 | 今天及未来 | 历史日期 |
|---|---|---|
| 普通 `pending` | 可按稳定键原位更新；目标候选不存在时删除 | 保留 |
| `inProgress` | 保留 | 保留 |
| `completed` | 保留 | 保留 |
| `skipped` | 保留 | 保留 |
| detached 单日覆盖 | 保留 | 保留 |

模板停用或软删除时，调用方传入空候选；服务只删除核对范围内今天及未来的普通 `pending` 实例。范围外实例不会被读取窗口误删。

## 3. 幂等和失败边界

- 业务唯一键继续使用 `templateID + dateKey`，已有实例原位更新，不采用先删后插。
- 相同候选重复核对不会改变实例 ID，也不会重复写入完全一致的快照。
- 候选日期、模板修订和存量日期/状态在任何模型修改前完成校验。
- 插入、更新和删除最后只调用一次 `ModelContext.save()`；持久化错误由调用用例层转换为用户可理解的反馈。
- 系统通知请求不在本服务内直接操作。实例删除产生的通知差集由 M4 的统一通知服务核对。
