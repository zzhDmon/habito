# Habito 体验优化修改计划

2026-10-10；基于`f2680a1`产品代码与`ab2eac3`审查记录。用户14:32已要求“开始执行，按节奏提交代码”，授权按本计划实施；单任务切换政策亦明确确认。实际状态以执行看板和实施任务卡为准。

## 推荐修改意见

### 1. 家长任务编辑：先避免误操作丢内容

- 返回或关闭时，只有输入发生实际变化才提示“修改还没保存”，按钮为“继续编辑”和“放弃修改”。默认保留编辑现场。
- 标题、星期、提醒时间、目标时长、外观、审核方式、奖励原始输入、可选计划/截止时间均纳入变化判断。输入改回原样不重复提醒；无效奖励输入也要保护。
- 保存失败留在表单，保留已输入内容；保存成功正常返回。放弃只丢弃本次草稿，持久化数据保持原值。
- 修改模块：TaskTemplateEditorViewModel、TaskTemplateEditorView、ParentGateView的离开协调。先枚举实际导航/关闭入口，不用单一禁止手势替代全部离开保护。
- 第一版使用离开确认，不加入自动保存或跨启动恢复，控制实现范围。

### 2. 孩子计时页：明确进展和下一步

- 保留“已专注 05:00”，增加“还差10分钟”；不足一分钟时显示“还差不到1分钟”，避免刚开始就把剩余分钟向下取整。达到目标显示“目标完成，可以打卡”；审核任务则提示“目标完成，可以提交检查”。
- 达标前开始/暂停/继续为主操作，完成/提交保持可用并排在稍后提醒之前；达标后完成/提交成为主操作，暂停仍有明确入口。两种状态下，“10分钟后提醒我”都放在最后。
- 提示只改变显示与操作层级，保留提前手动完成、二次确认、短时撤销以及原奖励/审核规则。
- 修改模块：TaskSessionScreenContent的纯显示状态、TaskSessionTimerPanel、TaskSessionControlsView、本地化与设计系统。时长计算使用现有注入时间，不另建后台秒计时器。

### 3. 专注镜头：有画面才占视频空间

- 运行并有可用镜头时，保留当前人物小窗及本地预览说明。
- 未开始时显示紧凑提示“开始计时后打开镜头”；暂停时显示“镜头已关闭”；无设备时显示“镜头不可用，仍可计时”。拒绝权限保留“去设置”，启动失败保留“重试”。
- 非运行状态移除可见的大黑占位，状态条随大字自然换行；不截断文案。视频区域大小与横屏方向不在本轮重新设计。
- 修改模块：TaskCameraPanel、镜头显示状态/文案、TaskSessionLoadedView与设计系统。保留必要的预览宿主连接，实际启停继续由现有服务管理；UI折叠不代替停机。

### 4. 第一次使用：让家长知道下一步

- 家庭尚未设置任务时，空态增加“请家长安排任务”，进入现有PIN门控。
- 家长进入后显示简短步骤“设置PIN→添加任务→检查提醒”，已完成项跳过；添加任务复用已有常用预设，不再做另一套创建流程。
- 已有任务但今天没有安排时显示“今天可以休息”；放假、全部完成和加载失败维持各自语义。
- 修改模块：Today查询/页面状态、KidTodayTaskContent、RootView与家长配置入口。首次判定依据家庭任务配置事实，不用“今日列表为空”代替；具体如何对待仅存归档模板，拆卡时明确。

### 5. 切换任务：推荐一次只专注一项，开始前确认

- **已确认的产品规则：** A正在运行时开始B，提示“阅读还在计时，要暂停阅读并开始口算吗？”；选择“切换任务”才暂停A并开始B，选择“继续当前任务”返回A。单纯返回首页或切到后台仍按原规则继续计时。
- 首页将活动会话区分为“正在计时”和“已暂停”，让孩子能看懂状态。
- 修改模块：跨任务计时用例/事务、TaskProgressService、Today状态映射、任务开始动作。必须处理通知跳转、跨午夜任务及存量多个运行会话；失败不能出现A已暂停但B没有启动的半完成结果。
- 用户已明确选择“一次只计一项”的推荐政策，已拆UX-C04A/B；按既定顺序实施，不在前面的小卡中顺手改计时规则。

上述方案已获实施授权；卡级实现与新源验收持续更新，未验收的实现不记作完成。

## 实施顺序与提交边界

|---|---|---|---|---|
| 第一轮 | UX-C01A 草稿变化与离开决策 | 可测试的初始快照、变化判断、离开意图 | 无修改/修改后改回/无效输入/保存失败/保存成功 | 相关单测与构建通过后独立提交 |

同一时刻只执行一张卡。按DEC-030，每张卡先做风险相关验证，完整回归集中在阶段收口；发现失败或新增风险再扩大测试，不逐卡重复整套UI。所有提交保留AI共同署名，不推送、不迁移正式家庭数据。用户批准实施后，按上述顺序创建正式任务卡；这张表不是已完成任务统计。
