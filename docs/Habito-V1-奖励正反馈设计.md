# Habito V1 奖励正反馈设计

> 2026-10-05。用户确认“正反馈强一点、和游戏一样”的方向（DEC-029）。以下为落实方向的设计草案，不替代待确认的奖励/宠物数值，也不宣称游戏化必然提高儿童积极性。效果需后续家庭试用观察。

## 1. 获得感来自三个连续、可信的结果

现实任务完成 → 真实 XP/Coin 入账 → 狗狗对这次努力作出积极回应。

孩子每次都能读懂“我做成了什么、获得了什么、成长了哪里”。不把动画数量等同激励强度；反馈有层次、与行动有关且随时可继续，不靠拉长等待。

## 2. 分层反馈候选

| 场景 | 设计候选 | 事实约束 |
|---|---|---|
| 普通确认完成 | 明显完成勾选、任务卡转为完成；狗狗欢快回应；真实奖励收据与资产增加 | 只有事务成功才庆祝入账；零奖励不显示伪造 +Coin，仍肯定现实努力 |
| 提醒前自主完成 | 比普通完成更突出的“你自己想到了！”标记；明确基础奖励与自主奖励的来源 | 仅基于提交快照；自主奖励未配置不假发，强调主动性也可不依赖 Coin |
| 提交等待家长验收 | 温暖的“已交给家长啦”与等待徽标 | 肯定提交动作但不演“到账”，不暗示已通过 |
| 家长通过验收 | 保存可回看的奖励收据；孩子下一次进入时看到本次到账与狗狗回应 | 不要求孩子守着 App 等验收；重复进入不重复结算/无限弹出 |
| 真实成长节点 | 狗狗成长展示、清楚的进度与下一目标；比普通完成更有仪式感 | 等级阈值/外观资产未确认前只设计接口，不猜具体节点 |
| 当天全部完成 | 一个更完整、但可直接继续的收尾庆祝，突出“今天的事情都做好了” | 待验收不伪装全部确认；重启/返回不反复制造新奖励 |
| 喂食 | Coin 消费成功后狗狗接住食物并回应，解释本次互动结果 | 必须真实扣账和记录同时成功；不让先播放动画掩盖消费失败 |

## 3. 游戏感的落地抓手

- **清晰结果**：奖励收据、完成徽标、进度变化三者表达同一事实；不要只有一条短暂 Toast。
- **宠物回应有关联**：阅读、运动、自主完成可有不同庆祝姿态或短句候选，避免每次相同“很好”。具体素材、数量和文案在 UI 卡中精炼。
- **小成功与大节点有差异**：普通完成短促，自主完成更突出，成长节点有仪式感；不为每次操作强制全屏长动画。
- **奖励可预期**：任务页展示已配置规则、到账时解释来源；不引入随机抽奖或在 App 内刷 Coin 的小游戏（沿用最小闭环范围）。
- **长期获得感可回看**：成长和收据来自真实账本与确认历史；观看/回放不再发奖励。

## 4. 交互与无障碍

- 复用现有 PRD 的短时反馈方向，具体节奏由 Preview/模拟器验证，不把未验证毫秒数硬编码到领域层。
- Reduce Motion 用明确的静态结果、轻淡入等替代大量飞入/缩放；信息完整不降级。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)
- VoiceOver 按语义说明确认/等待/实际奖励，不逐枚播报飞动 Coin；大字和横屏下收据不遮挡下一步。
- 声音/触觉为可选设计，不能假设目标 iPad 有触觉硬件；静音情况下核心反馈也完整。具体默认不在本次规则确认范围。
- 本地状态恢复后按稳定完成/提交 ID 识别收据；展示状态不得成为账本幂等键或财务真相。

## 5. 验收与待确认

- UI 验收：普通、自主、零奖励、待验收、退回、通过、消费失败、再次进入、Reduce Motion/VoiceOver/大字等场景不出现虚假入账；计时/通知原功能回归。
- 家庭观察：孩子能否说清奖励来源、是否更愿意自主完成、是否只反复打开宠物页；不能只以点击或停留时间评判成功。
- 待确认参数仍包括分类默认奖励、自主加成、等级、食物、Bond/Mood；先做独立候选数值表，再请用户确认。本设计文档不把参数后置误写成授权开发者自定。

## 6. M6-001A 当前实现切片（2026-10-06，软件验收完成）

- 普通确认完成：放大完成印章和“你做到了！”标题，以独立奖励卡展示本次真实 XP/Coin，不用仅一行 Toast 表达结果。
- 自主完成：仅真实收据 `beforeReminder` 才增加印章差异与“你自己记得做啦！”徽标；金额为收据原值，不在 View 重新加自主币。零奖励自主完成仍显示徽标和“这份努力已经记下啦”。旧未知自主性不回算。
- 等待：保留“已提交！”肯定和确认说明，新增“等家长确认，还没有到账”明确标识；没有完成印章或货币卡。
- 动态效果：设计令牌控制短促单次入场，不循环、不播放声音、不依赖触觉硬件。关闭按钮从出现起保持启用；Reduce Motion 策略第一帧就完整不透明、无缩放。正式组件读取只读系统设置，静态 Preview 接收显式展示策略，不伪造系统环境值。
- 生命周期：局部视图以原完成/提交 ID 标识，新事件才重建视觉状态；原用例负责关闭、刷新与撤销。没有改账本、延长撤销、历史重放或跨进程投递。
- 最终软件证据：两系最新完整单测各 400 定义/643 次、完整 UI 各 36/36、最大系统辅助字号四场景各 4/4，均通过；Release/静态分析/格式和 swiftui-pro 专项复核通过。静态纯策略及最大字号首帧原生渲染覆盖普通/自主/等待，不替代系统开关现场走查。实际截图已核对普通/自主真实金额和零奖励/等待无虚假货币，方向异常不作布局证据。
- 当前限制：Mac 锁屏，原生桌面控制无法打开模拟器设置；系统减少动态效果开关的现场走查未执行，静态策略测试/Preview 不冒称系统设置实测。实机 VoiceOver 手势和儿童积极性提升同样仍需设备/家庭观察。
