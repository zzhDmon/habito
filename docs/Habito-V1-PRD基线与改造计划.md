# Habito V1 PRD 基线与改造计划

> 制定日期：2026-09-29。来源为用户在“开源项目参考”对话中确认的新 PRD。本文用于说明新 PRD 相对当前 Habito V0 的差异、迁移边界和后续实施顺序；V0 的实时状态仍以《Habito-V0-执行看板》为唯一事实来源。

> 2026-10-04 状态补充：下文保留制定时的 M4-007 背景。M4-007 现已完成，当前为 M4-008 自动化集成与真机验收；目标设备仍离线。V1 决策与候选任务准备见《Habito-V1-决策草案与验收矩阵》，所有未确认细则仍是 `ASSUMPTION`，未进入正式模型。

## 1. 版本关系

- 当前 V0 是已经进入通知收口阶段的可运行技术底座，核心闭环为“任务配置 → 本地提醒 → 计时 → 手动完成 → 家长查看”。
- 新 PRD 定义 V1 产品方向，核心闭环升级为“现实任务 → XP/Coin → 宠物反馈 → 自主完成 → 习惯形成”。
- V1 是在 V0 上演进，不重建工程，不删除已经完成的计时、通知、日期覆盖、PIN、历史快照和本地优先能力。
- 在 V0 当前任务 `M4-007` 完成前，不把 V1 字段或页面顺手塞入当前实现；V1 从独立决策门开始。
- V0 的 44 张任务卡保留为历史与验收基线，不回写成 V1 范围。V1 任务在本文确定产品决策后再拆成可独立领取的任务卡。

## 2. V1 产品基线

### 2.1 产品定义

Habito 是一款面向 6～10 岁儿童及其家长的单设备 iPad 家庭工具。它通过现实任务、XP/Coin 经济和虚拟宠物反馈，帮助孩子逐渐从父母提醒过渡到 App 提醒，再过渡到自主完成。

### 2.2 北极星目标

V1 不以孩子在 App 内停留更久或完成更多任务为最终目标，而以“自主完成任务数 / 总完成任务数”作为核心效果指标。

产品成功路径：

```text
父母提醒完成
→ App 提醒完成
→ 提醒前自主完成
→ 连续自主完成
→ 降低外部奖励与提醒
→ 形成习惯
```

### 2.3 产品原则

1. 基础责任、成长任务和挑战任务使用不同奖励预期，不把所有行为商品化。
2. 未完成默认只是不获得奖励，不扣除已获得的 XP/Coin，不制造任务欠债。
3. 宠物只提供中性或正向反馈，不死亡、不生病、不离家，不因未完成任务而受伤或哭泣。
4. XP 表示成长且原则上只增加；Coin 表示选择权，可用于宠物食物、玩具等消费。
5. Coin 余额以不可变交易账本汇总为事实来源，不能只维护一个可直接改写的余额字段。
6. 奖励和提醒可以逐渐退坡，但 V1 只向家长提出建议，不自动修改规则。
7. 儿童端隐藏周期、奖励规则、统计和配置复杂度；家长端负责规则配置、必要验收和趋势判断。

### 2.4 V1 最小闭环

```text
家长创建周期任务
→ 系统生成今天的任务实例
→ 孩子完成任务
→ 系统按快照发放 XP + Coin
→ 孩子用 Coin 喂狗
→ 宠物给出积极反馈
→ 第二天继续
```

计时、稍后提醒和日期覆盖作为 V0 已有增强能力继续保留，但不是 V1 产品价值的唯一主轴。

## 3. 当前项目差异总览

| 领域 | 当前 V0 | 新 PRD / V1 | 修改结论 |
|---|---|---|---|
| 产品目标 | 到点提醒、计时并完成当天任务 | 提升自主完成率并形成习惯 | 重写产品指标与试用观察项 |
| 儿童首页 | 推荐“现在做什么”，围绕计时 | 按上午/放学后/晚上/全天分组，展示 XP/Coin 与宠物反馈 | 保留推荐卡，扩展分组、资产和反馈 |
| 任务类型 | 无业务分类 | 基础责任、成长任务、挑战任务 | 为模板增加分类并提供默认奖励策略 |
| 时间语义 | 一个计划/提醒时间 + 目标时长 | 计划时间、提醒时间、截止时间、时间段 | 扩展规则与实例快照，明确三种时间的边界 |
| 完成状态 | pending / inProgress / completed / skipped | 待完成、等待验收、已确认、未完成等 | 设计兼容旧状态的审批状态机，不直接重命名历史值 |
| 完成方式 | 孩子手动完成或家长更正 | 自行确认、家长验收、拍照记录 | 先加入自行确认和家长验收；拍照后置 |
| 自主完成 | 未记录 | 提醒前完成记为主动完成，可获额外奖励 | 依据规则快照判定并写入完成记录 |
| 奖励 | 明确不做复杂奖励 | XP + Coin、主动奖励、奖励退坡 | 新增奖励快照、发放服务与幂等账本 |
| 经济系统 | 无 | Coin 赚取、消费、储蓄目标 | 新增 CoinTransaction，所有余额由账本求和 |
| 宠物 | 无 | 一只狗，Level/Bond/Mood，食物与玩具 | 新增 Pet 领域和独立宠物页，禁止负向生存惩罚 |
| 成长系统 | 仅今日完成进度 | Streak、成就、7/14/30 天完成率与自主完成率 | 在可靠历史数据基础上新增派生统计 |
| 家长中心 | 任务、今日、日期覆盖、通知诊断 | 增加待验收、奖励规则、成长记录和习惯建议 | 保留现有入口与信息架构，增量加页 |
| 数据同步 | 单机本地 SwiftData | 仍以 Local First 为主；CloudKit 仅为候选 | V1 最小闭环不接 CloudKit，另立决策与迁移任务 |
| 页面规模 | 三张关键页面 + 家长子页 | 儿童 6 页、家长 8 页的完整产品结构 | 分批交付，不一次性铺开 14 页 |
| 成功标准 | 通知和计时技术闭环稳定 | 连续使用 14 天且部分任务出现自主完成 | V1 增加家庭试用与产品效果验收 |

## 4. 可直接复用的当前能力

以下能力已经有实现和验收证据，V1 应复用而不是重做：

- SwiftUI + SwiftData + Swift 6 严格并发的工程基线。
- `TaskTemplate`、`ReminderRule`、`TaskOccurrence`、`CompletionRecord`、`TimerSession` 的模板—实例—历史快照结构。
- 一次性/按星期规则、日期覆盖、单日覆盖、幂等实例生成和历史保护。
- 孩子今日页、任务执行/计时、完成与短时撤销。
- 家长 PIN、任务 CRUD、今日实例维护和上课/放假覆盖。
- 稳定通知 identifier、滚动预算、增量重建、点击路由和稍后提醒设计。
- 注入 Clock/Calendar/TimeZone 的时间测试边界，以及现有横屏、动态字体和无障碍基线。

## 5. 必须新增或调整的领域模型

### 5.1 现有模型增量字段

`TaskTemplate` 建议新增：

- `category`：`basicResponsibility` / `growth` / `challenge`。
- `timePeriod`：`morning` / `afterSchool` / `evening` / `allDay`。
- `verificationType`：`selfConfirm` / `parentApproval` / `photoRecord`。
- `xpReward`、`coinReward`、`activeBonusCoin`。
- 奖励退坡暂不单独自动化；V1 由家长编辑上述奖励字段。

`ReminderRule` 建议新增：

- `plannedTimeOfDayMinutes`：孩子预期开始的时间，可空。
- 现有 `timeOfDayMinutes` 保留为提醒时间，避免破坏既有通知代码。
- `deadlineTimeOfDayMinutes`：截止时间，可空。
- 保留现有 `once` / `weekly` 底层表达；“每天、工作日、周末、指定星期”是 UI 预设，不新增重复语义。

`TaskOccurrence` 建议新增快照：

- `categorySnapshot`、`timePeriodSnapshot`、`verificationTypeSnapshot`。
- `xpRewardSnapshot`、`coinRewardSnapshot`、`activeBonusCoinSnapshot`。
- `plannedAt`、`deadlineAt`；现有 `scheduledAt` 继续表示提醒时间，避免同时维护两个同义字段。
- 审批状态不要直接塞入现有 `status`；优先用独立 `verificationStatus`，兼容 `pending/inProgress/completed/skipped` 历史值。

`CompletionRecord` 建议新增：

- `completionTiming`：`beforeReminder` / `afterReminder` / `unknown`。
- `verificationStatus`、`verifiedAt`、`verifiedBy`。
- `baseXP`、`baseCoin`、`activeBonusCoin` 的最终发放快照或稳定关联。
- 图片证据若进入后续版本，只保存受控的本地资源标识，不在核心模型中裸存不稳定 URL。

### 5.2 新增模型

- `XPTransaction`：XP 发放账本；原则上只允许正向业务交易，纠错需有可审计冲正记录。
- `CoinTransaction`：Coin 收入、消费和调整账本；余额为交易金额合计。
- `Pet`：单只狗的名称、等级、亲密度、今日情绪和成长阶段。
- `PetItem`：食物/玩具定义、价格、亲密度效果和动画键。
- `PetInventory`：已购买且可持有/解锁的物品。
- `PetInteraction`：喂食、玩耍等行为及其 Coin 交易关联。
- `Achievement` / `AchievementRecord`：成就定义与解锁记录。
- `ChildProfile`：孩子昵称等展示资料；V1 仍只允许一个有效档案。

`ParentSetting` 不建议为了匹配 PRD 名称机械新增；当前 `AppSettings` 与 Keychain PIN 边界已经承担其职责，可按字段职责扩展。

### 5.3 事务与幂等边界

- “确认完成 + 写完成记录 + 发放 XP/Coin + 更新成就候选”必须通过同一个用例入口执行。
- 每次奖励交易必须有稳定业务幂等键，例如 `completionID + rewardKind`；重复点击、重启恢复和重复验收不能重复发奖。
- 家长拒绝验收时不发奖励；再次提交和最终通过的状态转换需要明确，不能删除原始提交痕迹。
- 修改模板奖励只影响尚未确认的未来实例；已确认任务的奖励和交易不可按新模板重算。
- 宠物消费必须同时校验账本余额并写入交易与互动记录；不能先改宠物、后扣 Coin。

## 6. 页面与交互改造

### 6.1 儿童端

1. 今日首页：保留当前推荐任务主卡，增加时间段分组、XP/Coin 展示和等待验收状态。
2. 任务详情：继续支持计时；完成按钮根据验收方式直接确认或提交等待验收。
3. 奖励反馈：确认完成后显示 0.8～1.5 秒的 XP/Coin 与宠物积极反馈，并遵循 Reduce Motion。
4. 宠物主页：只呈现一只狗的 Level、Bond、Mood 和可执行互动。
5. 喂食/玩耍：使用 Coin 或已解锁玩具产生正向反馈；不引入饥饿、生病、死亡。
6. 成长/成就：展示 Streak、成就和宠物成长，不展示排名或竞争。

### 6.2 家长端

1. 任务编辑器：增加分类、时间段、计划/提醒/截止时间、XP/Coin、主动奖励和验收方式。
2. 待验收：集中处理孩子提交的任务，支持通过和退回，并显示不会重复发奖的结果。
3. 今日概况：增加自主完成、待验收和连续完成信息。
4. 成长记录：提供最近 7/14/30 天完成率、自主完成率和每任务趋势。
5. 习惯建议：达到明确阈值时建议降低 Coin 或提醒强度；V1 不自动修改。

### 6.3 首次设置

- 在现有 PIN 设置后增加孩子昵称和宠物名字。
- 提供 3～5 个任务模板，不鼓励首次创建十几个任务。
- 默认奖励按任务分类给出，但必须允许家长调整。

## 7. 推荐实施顺序

### Gate V1-D：产品规则锁定

目标：先解决会改变状态机、账本和 UI 的冲突，不写业务代码。

- 确认 PIN 继续固定四位，还是升级为 4～6 位。
- 确认家长入口继续可见点击 + PIN，还是恢复长按 + PIN。
- 定义计划时间、提醒时间、截止时间以及“自主完成”的精确判定。
- 定义家长验收的退回、重新提交和撤销语义。
- 确认 Level 由孩子 XP、宠物 XP 还是二者映射；避免同一 XP 重复建模。
- 确认 V1 P0 是否包含宠物玩具；建议最小闭环先只做喂食，玩具列 P1。

退出标准：所有问题形成执行看板决策，状态机和奖励规则可以写成确定性测试。

### V1-M1：模型迁移与奖励内核

- 建立 SwiftData 新 schema 版本和真实旧库迁移夹具。
- 为现有模板/实例补兼容默认值，旧完成记录的主动完成状态记为 `unknown`，不得猜测。
- 新增 XP/Coin 账本、余额查询、奖励幂等键和事务用例。
- 覆盖重复完成、重复验收、撤销、模板改奖励和磁盘重开测试。

退出标准：旧 V0 数据无损打开；同一完成事件任何重复路径都只发一次奖励。

### V1-M2：任务分类、时间语义与自主完成

- 扩展家长编辑器和实例快照。
- 儿童今日页按时间段分组，同时保留当前推荐排序。
- 按实例的提醒时间快照判定提醒前/后完成，不依赖通知实际是否送达。
- 发放主动完成奖励，并在家长今日概况中展示来源。

退出标准：自行确认任务可以稳定产生基础奖励和主动奖励，历史不受模板修改影响。

### V1-M3：家长验收闭环

- 引入等待验收状态和家长待办页。
- 通过后一次性发奖；退回后允许重新提交；完成与通知清理语义保持一致。
- 拍照记录不与本阶段捆绑，先以手动验收验证闭环。

退出标准：孩子提交、家长通过/退回、重启恢复、重复操作和通知清理全部通过。

### V1-M4：单宠物与最小消费闭环

- 首次设置创建一只狗。
- 实现 Level/Bond/Mood 的最小规则和每日 Mood 重置。
- 实现少量食物、购买/消费、Coin 扣账和宠物正向反馈。
- 不做多宠物、抽卡、装备、战斗、疾病、死亡或小游戏刷 Coin。

退出标准：完成现实任务获得 Coin，并能可靠消费一次让宠物产生可理解反馈。

### V1-M5：成长、成就与奖励退坡建议

- 计算 Streak、7/14/30 天完成率和自主完成率。
- 儿童端展示正向成就；断连后展示历史纪录和重新开始文案。
- 家长端按任务显示趋势，并在阈值满足时建议降低 Coin 或提醒强度。
- 建议只读，不自动改规则。

退出标准：统计可由固定日期夹具复现，跨时区/缺失日期/跳过任务的分母语义明确。

### V1-M6：反馈动画、试用与放行

- 收口任务完成、奖励入账、全部完成和宠物反馈动画。
- 覆盖 Dynamic Type、VoiceOver、Reduce Motion、横屏与目标设备性能。
- 进行至少 14 天家庭试用，记录自主完成率、家长配置成本和孩子是否只沉迷宠物页。

退出标准：无 P0/P1；连续使用达到 14 天；至少一个任务出现可复核的自主完成趋势。

## 8. 优先级建议

### V1 P0

- 任务分类、时间段和计划/提醒/截止时间。
- 自行确认 + 家长验收。
- XP/Coin 奖励快照与幂等账本。
- 提醒前自主完成判定和额外奖励。
- 一只狗、Level/Bond/Mood、最小喂食消费。
- 家长今日概况和基础 7/14/30 天统计。
- 旧 V0 数据迁移与完整回归。

### V1 P1

- Streak 与成就。
- 宠物玩具和解锁互动。
- 奖励退坡与提醒退坡建议。
- 任务模板快捷创建。
- 拍照记录；先不做 AI 检查。
- CloudKit 备份可行性探针和独立决策。

### V1 P2 / 后续

- 现实奖励兑换、多孩子、多宠物、家庭账号、远程家长端。
- 排行榜、好友、社交、聊天、广告、会员和在线商城。
- AI 任务规划、AI 图片检查、语音助手和课程内容。

## 9. 迁移与回归重点

- 必须使用旧版本真实持久化库做迁移测试，不能只验证新建内存容器。
- 旧模板默认分类和奖励均需显式决定；在决定前不得静默给旧任务批量发 Coin。
- 旧完成记录没有“提醒前完成”的可靠证据，一律显示为未知，不回算主动奖励。
- 现有完成撤销窗口与已发奖励冲正必须统一设计；不能删除交易，也不能让账本余额失真。
- 等待验收的任务是否取消主提醒、是否允许稍后提醒，需要在 V1-D 决策后写入状态机。
- 任何新增实例快照都要继续满足“编辑未来、保护历史”的既有原则。
- V1 完整回归必须继续包含通知预算、日期覆盖、跨午夜、时区变化、PIN/Keychain 和横屏 UI。
