# Habito 对 Kado 的工程复用评估

## 结论

可以借鉴，但不应整体搬入。

本次核对的是 [scastiel/kado](https://github.com/scastiel/kado) 的提交
`a95ebb95ee6d5578ef08a49c4f16854b9339903a`（2026-09-20）。Kado 使用 MIT License，
允许使用、修改和分发；若未来复制其代码或其他实质性内容，必须在 Habito 中保留原作者
版权声明和完整 MIT 许可文本。

截至本评估，没有把 Kado 源码复制进 Habito；当前仅记录架构经验和后续实施路线。

## 值得采用

### 1. Debug/UI 测试使用独立存储和确定性种子

Kado 的 `UITestSupport` 与 `ScreenshotSeed` 通过启动参数切换到一次性测试存储，并写入
固定、可重复的数据；不会读取、删除或污染开发者的正式数据。

Habito 在 `M2-007` 采用同一原则，但按本项目模型重新实现：

- 仅在 Debug 编译中启用。
- UI 测试启动参数必须先把 SwiftData 指向独立临时存储，再执行重置或种子写入。
- 种子 ID、日期、排序和任务状态固定，覆盖待处理、运行中、暂停、完成及跨日进行中。
- 正式运行不识别测试参数，不提供孩子可见的调试入口。

这能直接解决 M2-007“没有家长 UI 时如何创建可走查任务”的问题，也可供后续截图回归使用。

### 2. 集中管理 UI 测试用无障碍标识

Kado 把标识集中在 `AccessibilityID`，并强调标识应放在按钮、输入框等叶子元素上，避免
SwiftUI 容器标识覆盖后代。

Habito 在 `M2-007` 新增自己的标识表，至少覆盖今日推荐卡、任务开始/暂停/继续、完成、
撤销和错误重试。标识使用稳定实例 ID 或固定语义值，不依赖中文文案，方便未来本地化后
继续运行 UI 测试。

### 3. 字符串目录覆盖测试

Kado 的 `LocalizationCoverageTests` 直接解析 `.xcstrings`，检查每个用户可见 key 都有非空
翻译。Habito 当前只有简体中文，也适合采用简化版：检查每个非豁免 key 都有非空
`zh-Hans` 值，并在未来增加语言时扩展列表。

该测试计划在 `M2-007` 与 UI 测试基础设施一起落地，防止页面只显示 key 或漏掉中文文案。

### 4. 导航只保存稳定 ID

Kado 明确避免把 SwiftData 托管对象放进导航状态，以防容器变化或对象失效时崩溃。
Habito 已经采用这一原则：今日查询生成只读值，任务页按 `TaskOccurrence.id` 重新查询；
无需额外改造。

### 5. 通知服务消费值快照

Kado 的通知调度协议由调用方提供习惯与完成值，调度器不直接查询 SwiftData。Habito 的
M4 也应保持“业务查询生成候选值，通知服务只核对系统请求”的边界。

但不能直接复制 Kado 的全量重排策略：Habito 还需要 48 条主提醒预算、稍后提醒预留、
稳定 request identifier、`NotificationLink` 映射和增量差集核对。

## 不采用

- Kado 最低 iOS/iPadOS 18；Habito 最低 iPadOS 17，不能直接使用其所有 API 与工程设置。
- Kado 的 CloudKit、多设备同步、Widget、App Intents、备份、评分、连续天数和小费模块不在
  Habito V0 范围。
- Kado 的可配置“每天开始时间”会改变日期归属；Habito 已确认按本地日历午夜跨日，并要求
  新一天显示“昨日任务仍在进行”，两者语义不同。
- Kado 的 Today View 直接持有 `@Query` 模型适合其工程，但 Habito 已确认 View 不直接编排
  SwiftData 读写，因此不替换现有 ViewModel/查询服务分层。
- 视觉组件与文案服务于成人习惯追踪，不直接套用到低年级孩子界面。

## 许可与接力规则

- 只借鉴思想、API 边界和测试策略时，在任务交接中注明参考来源即可。
- 若复制或紧密改写 Kado 的函数、类型或脚本，应在同一提交中新增第三方声明，包含
  `Copyright (c) 2026 Sébastien Castiel` 和完整 MIT License，并在代码注释中标出来源文件与
  上述提交哈希。
- 后续执行者不得因为许可证允许就整体引入 KadoCore；任何依赖或源码引入仍需符合 Habito
  “无未经确认第三方依赖”和当前任务卡范围。
