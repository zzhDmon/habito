# Habito M1 数据与规则内核验收报告

## 1. 结论

M1 数据与规则内核满足退出标准：给定模板、日历、日期覆盖与单日覆盖输入，可以稳定生成预期实例；重复核对不产生重复数据；计时和完成事实可跨磁盘重开恢复。目前没有已知数据一致性 P0/P1。

## 2. 已验证范围

- 公历本地日期、日期键、星期规则、月末、年末、闰日和夏令时边界。
- SwiftData 八模型、唯一键、关系、删除规则、磁盘两次重开和 PIN 存储边界。
- 放假过滤、撤销恢复、detached 单日恢复/替换及单日隔离。
- 实例稳定键幂等核对、模板修订、软删除、范围外保护和历史状态保护。
- 单活动计时会话、暂停/继续、前后台式时间戳恢复、多段累计、完成与撤销幂等。
- 跨服务磁盘闭环：规则 → 放假覆盖 → 实例 → 计时 → 完成 → 重开 → 模板修订 → 再次重开。

## 3. M2 查询契约

M2-002 的今日查询应以 `LocalDate` 作为日期输入，并由组合根注入 `Calendar`、`TimeZone` 和当前 `Date`。查询结果应是只读页面值，不把 SwiftData 模型直接交给 View，至少包含：

- 实例稳定 ID、`dateKey`、计划绝对时间。
- 标题、图标、颜色、目标时长快照。
- `TaskOccurrenceStatus` 与 `TaskOccurrenceOrigin`。
- 当前活动会话状态，以及按注入当前时间计算的有效活动秒数。
- 完成时间、实际活动秒数和完成来源（存在完成记录时）。

查询必须明确处理损坏原始值并向 Feature 层返回错误，不得把未知状态静默当成 `pending`。推荐排序属于 M2-002，不下沉到 SwiftData 模型或 View `body`。

## 4. 保留风险与后续边界

- iOS 17.2 runtime 在 Xcode 27 下存在测试宿主偶发无法握手的问题；最低目标持续以 `build-for-testing` 验证，完整测试运行在 iOS 27 模拟器。
- 系统时间倒退时计时服务明确报错；M2 需要提供用户反馈，M5-004 再做真机时间/时区验收。
- 通知请求是实例的派生数据，系统挂起请求的清理由 M4 统一核对，M1 不直接操作通知中心。
- `ASSUMPTION`：撤销完成后重新计时会累计旧会话实际用时；若产品决策改为清零，需要在 M2 交互实现前调整。
