## 1. V0 目标与边界

### 1.1 唯一核心闭环

家长创建“每天 19:30 阅读 15 分钟” → iPad 在约定时间发出本地通知 → 孩子打开当天任务并计时 → 孩子完成打卡 → 家长查看当天记录。

V0 成功不以功能数量衡量，而以这个闭环在孩子日常使用的 iPad 上是否稳定、是否足够简单来衡量。

### 1.2 V0 范围

- 家长创建、编辑、停用、删除任务模板。
- 设置任务名称、图标/颜色、计划时间、目标时长、每周重复日。
- 家长为具体日期标记“上课”或“放假”，也可调整某一天的任务。
- 孩子查看今天任务、当前应做任务和今日完成进度。
- 孩子开始、暂停、继续计时，并完成打卡。
- 孩子选择“稍后提醒”，V0 固定延后 10 分钟。
- 家长查看今日任务状态和完成记录。
- 本地持久化、本地通知、通知权限状态提示和通知重建。

### 1.3 明确不做

- 系统日历同步、中国法定节假日自动同步。
- 云端账号、远程家长端、多设备同步和数据备份。
- 语音录入、家长录音通知、孩子语音学习交互。
- AI 答疑、拍照批改、课程资源库、复杂积分商城。
- 可保证响铃的闹钟、关键警报或绕过专注模式的提醒。

## 3. 用户流程

### 3.1 首次设置（家长）

1. 首次打开进入简短说明，解释 Habito 的用途和本地存储方式。
2. 创建家长四位 PIN。
3. 创建第一个任务，默认示例为“阅读 15 分钟”。
4. 保存任务前展示提醒用途说明，再请求通知的提醒与声音权限。
5. 保存后展示下一次提醒时间；若权限被拒绝，任务仍可保存，但明确显示“提醒未开启”及前往系统设置的入口。
6. 返回孩子首页，立即看到今天的任务。

### 3.2 孩子每日主流程

1. 打开 App，首页优先展示“现在做什么”。
2. 推荐优先级：正在计时的任务 > 已到时间且未完成的最早任务 > 最近即将开始的任务 > 其余未完成任务。
3. 点任务大卡进入任务页，点击“开始”。
4. 计时过程中可暂停/继续；锁屏或切到后台后，以时间戳计算实际经过时间，不依赖后台持续执行计时器。
5. 点击“完成”，生成不可随模板修改而变化的完成记录，返回首页并更新今日进度。
6. 若暂时不做，点击“稍后提醒”，安排 10 分钟后的一次性通知；任务仍保持未完成。
7. 所有任务完成后显示简洁的完成态，不加入复杂奖励系统。

### 3.3 通知进入流程

1. 到点时由系统展示本地通知；App 关闭或在后台时不要求 App 自身运行。
2. 点击通知打开对应的当天任务实例，而不是任务模板。
3. 若实例已完成、已跳过或已删除，进入首页并给出“任务已处理”的轻提示。
4. V0 不在通知上放“完成”动作，避免孩子未实际执行就误完成；可保留“稍后提醒”作为后续增强项，V0 先在 App 内操作。

### 3.4 家长管理流程

1. 孩子首页右上角长按家长图标，输入 PIN。
2. 查看今日任务：未开始、进行中、已完成、已跳过及实际用时。
3. 新建或编辑任务模板；保存后只影响今天尚未开始的实例和未来实例，不改历史完成记录。
4. 修改当天实例时，只影响当天，不反写模板。
5. 删除模板前明确说明影响范围；确认后停用模板、删除未来实例和关联待发送通知，保留历史实例和完成记录。
6. 在日历中标记放假/上课；变更后重建受影响日期的任务实例和通知。

## 4. 三张关键页面

### 4.1 页面一：孩子首页 / 今日

目标：孩子无需阅读说明就知道现在该做什么。

- 顶部：日期、简短问候、家长入口。
- 主卡：当前推荐任务的大图标、短标题、计划时间、目标时长、主按钮“开始/继续”。
- 接下来：按时间排列的今日任务大卡，状态使用图形和文字共同表达，不能只靠颜色。
- 底部：今日完成数与总数，例如“今天完成 2 / 4”。
- 空状态：今天无任务、今天全部完成、提醒未开启分别使用不同文案。
- 交互约束：主要点击区域至少 44×44 pt；关键操作一步可达；孩子模式不出现删除、编辑等管理操作。

### 4.2 页面二：任务执行 / 计时

目标：一次只关注一件事。

- 顶部：返回、任务名称、任务图标。
- 中部：大号剩余时间或已进行时间；V0 默认显示“已进行 / 目标时长”，避免倒计时归零被误解为自动完成。
- 主操作：开始；进行后变为暂停/继续。
- 次操作：完成、稍后提醒。
- 状态处理：若离开后返回，根据持久化的 `startedAt` 与累计暂停时长恢复显示。
- 完成确认：短时误触可撤销 5 秒；超过窗口后由家长在记录中更正，避免复杂编辑流程进入孩子界面。

### 4.3 页面三：家长中心

目标：在一处完成 V0 所有配置和核对。

- 顶部概览：通知授权状态、已排程覆盖到的日期、今天完成情况。
- “任务”区：模板列表、启用状态、新建按钮；点项目进入编辑表单。
- “今日”区：当天实例与实际完成记录，可单独调整、跳过或恢复。
- “日历”区：按日期标记上课/放假。
- 任务编辑表单字段：名称、图标/颜色、计划时间、目标时长、重复星期、启用状态。
- 危险操作：删除模板必须二次确认，并明确“历史记录保留，未来提醒取消”。

说明：为保持三张核心页面，任务编辑器和日期选择器以家长中心内的 sheet/子页面呈现，不计为一级页面。

## 5. 数据模型

所有 ID 使用稳定 UUID；所有绝对时间使用 `Date` 保存，日历日期另存本地日期键；展示和实例生成统一使用设备当前时区与 `Calendar`。

### 5.1 `TaskTemplate`：任务模板

- `id`
- `title`
- `iconName`
- `colorToken`
- `targetDurationSeconds`
- `isEnabled`
- `createdAt`、`updatedAt`
- `archivedAt`：软删除时间；历史记录仍可引用。

关系：一个模板拥有一个提醒/重复规则，可生成多个特定日期任务实例。

### 5.2 `ReminderRule`：重复与提醒规则

- `id`
- `taskTemplateID`
- `scheduleType`：`once` / `weekly`
- `timeOfDayMinutes`：从本地午夜起的分钟数，避免仅保存某天的绝对时间。
- `weekdays`：星期集合；一次性任务为空。
- `oneOffDateKey`：一次性任务使用。
- `startDateKey`
- `endDateKey`：可空。
- `isEnabled`

V0 不用系统重复通知直接表达业务重复；规则先展开为具体日期实例，再为实例安排一次性通知，以便支持放假日和单日修改。

### 5.3 `TaskOccurrence`：特定日期任务实例

- `id`
- `templateID`：保留对来源模板的引用。
- `dateKey`：如 `2026-09-22`，按当前本地日历解释。
- `scheduledAt`
- `titleSnapshot`、`iconSnapshot`、`colorSnapshot`、`targetDurationSnapshot`
- `status`：`pending` / `inProgress` / `completed` / `skipped`
- `sourceRevision`：生成时模板版本，用于判断未来实例是否需重建。
- `isDetachedOverride`：是否为当天单独修改。
- `createdAt`、`updatedAt`

唯一约束：同一模板、同一 `dateKey` 最多一个有效实例。快照字段保证模板改名后历史仍按当时内容展示。

### 5.4 `CompletionRecord`：完成记录

- `id`
- `occurrenceID`
- `completedAt`
- `activeDurationSeconds`
- `completionSource`：V0 为 `childManual` 或 `parentCorrection`。
- `createdAt`、`updatedAt`

说明：实例描述“这一天应该做什么及当前状态”，完成记录描述“实际上何时、用了多久完成”，两者不合并。

### 5.5 `TimerSession`：可恢复计时状态

- `id`
- `occurrenceID`
- `state`：`running` / `paused` / `ended`
- `startedAt`
- `lastResumedAt`
- `accumulatedActiveSeconds`
- `endedAt`

同一实例只允许一个未结束计时会话。运行中经过时间通过 `当前时间 - lastResumedAt + accumulatedActiveSeconds` 计算。

### 5.6 `DayOverride`：日期类型覆盖

- `id`
- `dateKey`
- `dayType`：`schoolDay` / `holiday`
- `note`：可空。
- `updatedAt`

未覆盖日期按自然星期解释：周一至周五为上课日，周末为放假日。该默认规则属于假设 A9 的配套行为。

### 5.7 `NotificationLink`：通知映射

- `requestIdentifier`：稳定格式，例如 `occurrence.<occurrenceID>.primary` 或 `occurrence.<occurrenceID>.snooze.<timestamp>`。
- `occurrenceID`
- `kind`：`primary` / `snooze`
- `scheduledAt`
- `createdAt`

它用于精确取消、审计和对比系统当前挂起请求；业务正确性不能只依赖这张表，重建时还需与系统实际挂起列表核对。

### 5.8 `AppSettings`

- 家长 PIN 的安全摘要与盐，不保存明文。
- 首次设置状态。
- 上次成功生成实例时间、上次成功调度时间、调度覆盖截止日期。
- 上次读取到的通知授权状态。
- 当前模型/迁移版本。

## 6. 提醒调度与更新策略

### 6.1 基本原则

- 每个 `TaskOccurrence` 对应一个非重复的日历通知请求。
- 不使用后台常驻计时，也不依赖 App 到点时仍在运行。
- 系统负责在 App 未运行或后台时展示已成功安排的本地通知，但交付时间并非绝对保证；系统通知权限、专注模式、通知摘要和声音设置均可能影响表现。
- 先生成实例，再由实例生成通知；通知只是业务数据的派生结果，可随时重建。

### 6.2 滚动排程

- 每次重建从“现在”开始，按 `scheduledAt` 升序生成未来实例。
- V0 预留系统请求余量，主提醒最多保持未来最近 48 条；稍后提醒最多占 8 条。具体上限在目标 iPadOS/SDK 确认后复核。
- 家长中心显示“提醒已安排至 YYYY-MM-DD”，低于未来 7 天时显示黄色提示。
- 每次 App 冷启动、进入前台、完成首次设置、保存/停用/删除模板、变更日期类型、改单日实例、完成任务或创建稍后提醒后，执行增量核对与补排。
- 若家庭每天使用 App，打开 App 会自然补足未来排程；若长期不打开，覆盖日期之后不承诺继续提醒，这一点必须在 V0 说明中可见。

### 6.3 可重复执行的重建算法

1. 读取通知授权和声音/提醒设置。
2. 将模板规则展开为未来候选实例；保留已开始、已完成、已跳过和单日覆盖实例。
3. 应用 `DayOverride`：放假日移除尚未开始的普通学习实例，显式恢复/单日新增除外。
4. 根据模板版本更新今天尚未开始及未来的非覆盖实例；历史实例不变。
5. 计算未来最近 48 个应提醒的待处理实例。
6. 获取系统实际挂起请求，以稳定 identifier 做差集：取消已失效项，保留完全一致项，新增或替换发生变化的项。
7. 写入 `NotificationLink` 和覆盖截止日期；任何一步失败都在家长中心显示可重试的错误状态。

### 6.4 编辑、删除和完成后的行为

- 编辑模板：取消该模板尚未触发的关联通知，更新今天尚未开始及未来非覆盖实例，再重排。
- 编辑当天：只替换该实例的通知，不修改模板或其他日期。
- 删除模板：采用软删除；取消所有未来关联通知，删除未来未开始实例，保留过去实例和完成记录。
- 完成任务：取消该实例的主提醒和稍后提醒，清理已送达的关联通知。
- 稍后提醒：取消同实例之前的稍后提醒，仅保留最新一次；若延后时间跨过当天午夜，则不创建并提示孩子找家长处理。
- 通知授权关闭：不反复弹系统授权框；家长中心显示状态和“打开系统设置”。任务、计时和打卡仍可用。

### 6.5 日期、时区与系统时间变化

- `dateKey + timeOfDayMinutes` 是计划语义，`scheduledAt` 是在当前时区下的派生结果。
- 检测显著时间变化、时区变化以及 App 重新进入前台后，重新计算未来实例的 `scheduledAt` 并重排。
- 已完成记录的绝对时间不随时区变化。
- 跨午夜仍在计时的任务保留原实例归属；完成记录写真实完成时间，今日页在新一天显示“昨日任务进行中”。该行为需实机验收。

## 7. 开发任务拆分

以下工期是单人、首次正式开发 SwiftUI 应用的粗略假设，不是承诺；建议按纵向切片验收，而不是先把所有基础层写完。

### M0：工程与风险探针（1–2 天）

- 创建 SwiftUI iPad 工程，锁定最低系统与横竖屏策略。
- 在目标 iPad 上跑通免费签名安装。
- 做最小通知探针：前台、后台、锁屏、App 被终止。
- 记录目标设备、iPadOS、Xcode、签名方式和测试时间。
- 退出标准：已确认该设备能安装运行，并拿到真实通知行为证据。

### M1：本地领域模型（1–2 天）

- 建立上述 SwiftData 模型、仓储边界和模型版本。
- 实现星期规则展开、日期覆盖、实例生成和历史快照策略。
- 为规则展开、模板修改、放假覆盖、跨日/时区边界写单元测试。
- 退出标准：给定模板与日历输入，可稳定得到预期实例，重复执行不产生重复数据。

### M2：最小孩子闭环（2–3 天）

- 孩子首页、推荐任务排序、空状态和进度。
- 任务执行页、开始/暂停/继续、前后台恢复、完成与撤销。
- 完成记录落库并可在当天重新打开后恢复。
- 退出标准：不依赖通知也能完整完成一次当天任务。

### M3：家长配置闭环（2–3 天）

- 家长 PIN 与入口。
- 任务模板列表、新建、编辑、停用、软删除。
- 今日实例查看与单日调整。
- 日期上课/放假覆盖。
- 退出标准：交接稿中的“每天 19:30 阅读 15 分钟”可完全通过 UI 配出，且修改不污染历史。

### M4：提醒闭环（2–3 天）

- 上下文式通知授权请求与授权状态展示。
- 通知 identifier、滚动排程、系统挂起请求核对、增量重建。
- 通知点击深链到当天实例，完成后清理通知。
- App 内“稍后提醒 10 分钟”。
- 退出标准：锁屏/终止状态到点提醒、点击直达、编辑/删除后旧通知不再出现。

### M5：实机稳定性与可用性收口（2–4 天，另含 7 天签名观察窗口）

- 按第 8 节执行完整矩阵并保留截图/录屏/日志。
- 覆盖通知关闭、声音关闭、专注模式、重启、跨午夜、时区变化。
- 完成基本可访问性检查：动态字体、VoiceOver 标签、对比度、触控区域。
- 观察免费签名到期前后行为并形成结论。
- 退出标准：无 P0/P1 缺陷；已明确哪些行为是系统限制，哪些是应用缺陷。

### 推荐里程碑

- 可演示 V0：约 8–13 个开发日。
- 可交给孩子试用：约 10–17 个开发日，外加完整的签名到期观察窗口。
- 语音场景只有在 V0 日用闭环通过后再选型和排期。

## 8. iPad 实机验收标准

### 8.1 测试基线

验收记录必须包含：iPad 型号、iPadOS 版本、Xcode 版本、构建号、签名类型、通知设置、专注模式/通知摘要状态、设备时区。具体设备信息目前未确定，属于阻塞最终验收而非阻塞开发计划。

### 8.2 P0 核心闭环

| 场景 | 操作 | 通过标准 |
|---|---|---|
| 首建任务 | 创建今天稍后 2 分钟的“阅读 15 分钟” | 首页立即出现正确卡片；家长中心显示下一次提醒和排程覆盖日期。 |
| 锁屏提醒 | 保存任务后锁屏 | 在系统允许提醒与声音的前提下，通知在计划时间附近出现；记录实际偏差。V0 目标偏差不超过 60 秒，但系统明确不保证绝对准时，超差需区分系统策略与应用未正确排程。 |
| App 被终止 | 从多任务界面结束 App 后等待提醒 | 通知仍由系统显示；点击后重新启动并进入对应当天任务。 |
| 计时恢复 | 开始计时，锁屏 2 分钟后返回 | 显示的有效时长与真实经过时间一致，误差不超过 2 秒；不出现归零或重复计时。 |
| 完成打卡 | 计时后点完成 | 首页进度立即更新；重启 App 后状态与实际用时仍在；该实例不再产生提醒。 |
| 历史隔离 | 完成后修改模板名称和时长 | 已完成记录仍显示完成时的标题、目标时长和实际用时。 |

### 8.3 通知变更与清理

| 场景 | 通过标准 |
|---|---|
| 改时间 | 原时间对应的挂起请求消失，新时间只保留一条；两个时间点均实测，不得收到旧提醒。 |
| 改重复星期 | 被移除日期不再有实例/提醒，新增日期出现实例/提醒，历史不变。 |
| 单日修改 | 仅当天时间变化，后续重复计划不变。 |
| 删除模板 | 所有未来提醒取消；未来未开始实例移除；历史完成记录仍可查看。 |
| 标记放假 | 当天普通学习任务和提醒移除；撤销放假后按模板恢复且无重复。 |
| 稍后提醒 | 同一实例连续操作两次后只保留最后一次稍后提醒；完成任务后稍后提醒取消。 |
| 重复重建 | 连续进入前台、连续保存同一配置 5 次，实例和系统挂起请求均不重复。 |

### 8.4 权限与系统状态

| 场景 | 通过标准 |
|---|---|
| 首次拒绝通知 | 任务仍能创建；孩子可手动完成；家长中心明确显示未授权，且不伪装为“提醒已安排”。 |
| 设置中关闭通知 | App 下次进入前台能发现变化并提示；不崩溃、不丢任务。 |
| 只关闭声音 | 家长中心区分“通知可见”和“声音关闭”；验收不把无声音判作应用调度失败。 |
| 专注模式/通知摘要 | 记录系统实际表现；产品内不承诺绕过系统策略。 |
| 设备重启 | 重启后不先打开 App，已安排的近期通知仍需实测；随后打开 App，数据完整且排程核对成功。 |
| 时区变化 | 切换时区并重开 App，未来任务仍按本地计划时刻显示与提醒；历史绝对完成时间不被改写。 |
| 跨午夜 | 23:59 开始任务，次日完成 | 不丢失计时；记录归属原任务日期；新一天首页不会生成重复实例。 |

### 8.5 免费签名到期专项

该项是观察性验收，不预设“到期后 App 和通知仍可正常使用”。

1. 安装当天记录签名时间、预期到期时间、构建号和 Bundle ID。
2. 到期前安排一条跨过预期到期时点的本地通知，并保留系统挂起请求截图或调试记录。
3. 到期后分别验证：App 能否启动、已安排通知是否显示、通知点击结果、数据是否仍在设备容器中。
4. 用同一 Bundle ID 重新签名安装，再验证旧数据是否保留、通知是否需要重建。
5. 把观察结果写入测试记录，不将某一次系统版本上的表现推断为长期保证。

V0 的产品结论标准：只要签名到期导致 App 无法启动、提醒不可持续验证或需人工频繁续签，就判定免费签名“不满足长期每日使用”，但不阻塞开发期体验验证；长期试用前必须确定稳定分发方案。

### 8.6 缺陷分级与放行门槛

- P0：数据丢失、错误任务被完成、删除后仍提醒、核心闭环无法完成。不得放行。
- P1：终止/锁屏后应用侧未正确排程、计时明显错误、历史被模板修改污染。不得交给孩子日用。
- P2：布局、文案、轻微时间显示或可访问性问题。可记录后试用，但需有修复计划。
- 系统限制：授权关闭、专注模式、通知摘要、系统未保证的及时性。必须清楚提示并记录，不伪装成应用可控制能力。

## 9. 开工前最少需要确认的事项

以下问题不会阻止先做技术探针，但会影响正式工程配置或交互：

1. 目标 iPad 型号、当前 iPadOS 版本、是否为孩子专用设备。
2. 家长入口采用四位 PIN，还是只做长按防误触。
3. 放假日是否默认跳过全部任务，是否存在“假期也要做”的任务。
4. V0 是否只支持一个孩子。
5. 横屏、竖屏或两者都需首发支持。
6. 长期试用是否愿意加入付费 Apple Developer Program，或采用其他正式分发方式。

语音优先场景和首个学科模块不影响本 V0 核心闭环，可在 V0 实机闭环通过后单独决策。

## 10. 建议的 V0 决策门

- 决策门 1：M0 后确认本地通知与目标设备可行，再继续完整 UI。
- 决策门 2：M4 后让家长和孩子连续试用 3 天，观察是否真的每天打开、是否理解“现在做什么”。
- 决策门 3：完成免费签名到期观察后，决定长期分发方式。
- 决策门 4：V0 连续使用有效后，只选择一个语音场景进入下一版，不并行加入三类语音需求。
