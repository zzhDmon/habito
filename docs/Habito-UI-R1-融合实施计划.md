## 5. 视觉与资产约束

- 采用交接稿的“日系漫画成长冒险”方向：55%漫画、30%宠物RPG、15%高光反馈作为设计意图，儿童端明显漫画化，家长端优先效率。彩色漫画、可爱但不低幼，不模仿具体动漫IP。
- 图标以Tabler为单一主开源系统；SF Symbols保留系统导航/关闭/编辑等语义；XP、专有Coin、狗粮与漫画特效才定制。统一语义入口，按需打包静态矢量资源，不为图标引入运行时依赖。
- 已核对[Tabler官方仓库](https://github.com/tabler/tabler-icons)：提供SVG、统一24×24网格/2px描边及MIT许可说明。落地时固定来源版本、保留许可证和来源清单、验证Xcode资源渲染；本轮没有下载或引入资源/依赖。
- 中文正文保持系统语义字体。展示字体、具体配色和小狗品种/配饰尚需样稿，不把原稿色值当成已经过对比度验收的最终值。
- 角色先母版后状态，关键文案保留中文可读表达；漫画英文/拟声词作装饰，不能成为唯一状态说明。
- 继续iPadOS 17、SwiftUI、严格并发、44 pt、Dynamic Type、VoiceOver语义、Reduce Motion/Transparency。首页装饰不引入常驻复杂粒子或每卡独立计时器。

## 6. 原稿示例与已确认业务的冲突处理

| 原稿内容 | 本项目处理 |
|---|---|
| 自主完成示例“+10 Bonus XP” | 当前配置是XP/基础Coin/自主Coin。示例不能新增自主XP奖励；展示必须来自真实收据 |
| Today Clear展示今日XP/Coin | 是统计展示，不能再发一笔通关奖；需明确当日归属、审核跨日与冲正口径并测试 |
| 连续天数、稀有奖励、特殊成就、玩具 | 不因插画或组件清单纳入P0；Streak/成就仍为P1，玩具后置 |
| 等级、Bond/Mood、饥饿/食物价格及效果 | 对应产品规则未确认；角色表情资产不能暗含新的数值系统或未完成惩罚 |
| 更强Haptic、声音接口 | 用户此前明确后置，维持后置；不为未定能力先造空服务，不把iPad触觉当必备验收 |
| 多格Today Clear/全屏Level Up | 信息与继续动作不等待分镜播放；保留去重、零奖励、等待不算完成、失败可重试和Reduce Motion静态结果 |
| “冻结Pet Economy” | 当前宠物经济尚未完成；新业务按独立V1卡实现，完成后的规则才作为视觉层不可改变的输入 |
| 七组全部完成后才能开始UI | 本轮提出分阶段前置建议；保留当前B3C范围，不在回归中改源，不自动批准全量重写 |

## 7. 验证与当前停止点

卡级执行相关确定性单测、构建/严格质量、必要UI专项和视觉检查；数据迁移、扣币、失败回滚、幂等、跨进程与奖励资格不能省。每个新UI组件从首版覆盖普通/MAX、横屏、长文、空/错/完成和减少动态效果。

视觉基础阶段不跑无关完整UI；儿童样板做受影响主链路；宠物/喂食功能整合做事务与交互专项；最终整体验收在同一源上集中执行。UI定位变化可以更新测试定位，不得删除金额、状态、去重、撤销期限或热区断言。
