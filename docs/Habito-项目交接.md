# Habito：小学学习与自律工作台

> 供 Codex 项目继续规划使用。整理日期：2026-09-22。本文是对话交接摘要，不等于已经确认的完整 PRD。

## 用户目标与背景

- 为自己的小孩做一个主要运行在 iPad 上的学习、自律工作台；家长负责配置，孩子每天使用。
- 需要每天定时提醒要做什么，支持录制语音或语音输入；希望逐步加入小学学习相关的工作台功能。
- 用户是 React/TypeScript 前端工程师，有 MacBook Pro M1，计划独立开发。
- 孩子处于小学低年级阶段，因此主界面宜使用大图标、短文案、少步骤。

## 当前达成的方向

1. 首选 iPad 原生 SwiftUI。先做单设备、本地优先版本；不预设服务端、跨端或 AI Agent 是首版必需品。
2. 核心体验：打开即看到“现在做什么”、今天接下来的安排、完成进度。家长入口独立于孩子使用界面。
3. 第一个纵向闭环：家长创建“每天 19:30 阅读 15 分钟” → iPad 本地通知 → 孩子打开任务卡 → 计时 → 完成打卡 → 家长能看到记录。
4. 先用 App 自己的任务和日程模型，不依赖系统日历。EventKit 只在需要读取/写入系统日历时接入，它不会自动处理中国调休。
5. 工作日首版支持周一至周五及家长手动指定上课/放假日期。节假日自动数据源以后再评估。
6. 技术候选：SwiftUI、SwiftData、本地音频文件、UserNotifications、AVAudioRecorder。模型应分离任务模板、特定日期任务实例、完成记录和提醒规则，避免修改模板污染历史。

## 语音需求要分清

- **语音录入任务**：家长说“每天七点半提醒读书”，语音转文字并解析时间/重复规则；解析后由家长确认再保存。适合第二阶段。
- **家长录音提醒**：家长录一句短语，任务到点时作为通知声音或打开 App 后播放。通知声音有格式与时长限制，且通知受权限、专注模式等系统行为影响；不能承诺等同持续响铃的系统闹钟。首版可先做文字通知与默认声音，随后验证短录音提醒在真实 iPad 上的体验。
- **孩子语音学习交互**：例如朗读、问答、作业辅导，是更大的独立模块；目前还未定义，不应混进第一个开发闭环。

## 免费安装的现实约束

免费 Apple 开发账号可以用于 iPad 实机开发测试，但免费配置文件约 7 天过期，需要重新构建/安装或续签。它适合验证体验，不适合作为依赖每日提醒的长期部署方案。先验证持续使用的价值，再确定长期分发方式与是否加入付费开发者计划。不要以第三方自动续签作为产品可靠性假设。

## 建议的首版范围

- 家长：创建/编辑任务、选择具体时间与重复规则、设置时长、查看今日完成记录、为日期标记不上课。
- 孩子：今日任务大卡、开始/暂停计时、完成打卡、稍后提醒、当天进度。
- 系统：本地存储、请求通知权限、在任务编辑后重建受影响的本地通知；处理时区、日期变化和通知授权关闭。
- 暂缓：系统日历双向同步、云端账号、多设备同步、AI 答疑、拍照批改、课程资源库、复杂积分商城。
