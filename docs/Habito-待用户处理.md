# Habito 待用户处理清单

> 更新日期：2026-10-04。你离开电脑期间，开发者会继续完成可独立验证的代码、测试、文档与阶段提交；以下项目需要真实设备、家庭观察或产品决定，不能由自动化替代。

## 1. 连接目标 iPad

- 将目标 iPad A16 连接到 Mac，保持解锁、信任此电脑并启用开发者模式。
- **先不要覆盖安装新构建**：旧免费签名预计 2026-09-29 到期。先试一次旧 App 能否启动、通知点击结果、数据是否仍在，记录当前系统版本和结果；如果未提前安排跨期通知，该项记为“缺少前置观察证据”，不可补造。
- 之后可用同 Bundle ID 的新签名版本覆盖安装并验证数据保留。不要卸载旧 App；卸载会移除本地家庭数据库，破坏重签名保留验证。
- 连接后按《Habito-M4-验收记录》第 3 节执行实际送达矩阵。锁屏、专注模式与声音的真实观察仍需人在设备旁记录。

## 2. 家庭试用与长期分发

- M5 要求真实连续三天家庭使用，每天至少一次创建/提醒/计时/完成/查看记录闭环；记录孩子是否主动打开、误触、遗漏提醒和家长维护成本。
- 确认设备是否主要由孩子使用。
- 开发期免费签名不等于长期可持续分发；正式日用前需决定稳定分发方案。付费 Apple Developer Program 或其他分发成本不能由开发者自行购买。

## 3. V1 产品规则

现有新 PRD 与改造计划中的以下推荐值仍是 `ASSUMPTION`，尚未被本清单转成已确认决策：

| 决策 | 推荐值 | 为什么要明确 |
|---|---|---|
| 家长 PIN / 入口 | 沿用四位 PIN + 可见点击入口 | 已有可靠实现与无障碍路径，可避免无必要迁移 |
| 自主完成 | 严格早于实例的提醒时间快照；等于/晚于提醒不算自主 | 系统实际送达无法作为可靠时间真相 |
| 验收退回与重提 | 保留历次提交，退回后可重提；最终通过只发一次奖励 | 决定状态机与幂等键 |
| 完成撤销 | 保留原奖励交易，新增冲正；不删除账本历史 | 保证余额与历史可追溯 |
| XP 与宠物等级 | 一个 XP 总账；宠物成长阶段由累计 XP 映射 | 避免维护两套互相矛盾的等级体系 |
| 旧任务迁移 | 奖励默认为 0，旧完成时间类型为未知，不补发历史奖励 | 避免迁移时意外发奖或伪造自主完成 |
| 等待验收的提醒 | 建议不再提醒孩子做已提交任务，验收完成前不发奖励 | 决定旧计时/通知与新审批状态的衔接 |

你返回后可以一次性确认推荐值，或逐项给出不同选择；确认前保留 V0 数据、通知和计时行为，V1 的冲突性业务规则不静默落入正式库。
