# Habito V1 任务卡

> 2026-10-05 建立。V0 44 张卡保留原始验收；V1 状态唯一记录在《Habito-V0-执行看板》。先读看板，再读当前卡。确认规则见《Habito-V1-已确认规则》。每卡独立验证、阶段本地提交；不推送、不操作家庭数据。

## V1-D-001 确认规则、任务拆分与正反馈设计方向

- 依赖：用户实际确认清单 1～13，已取得。
- 范围：决策可追溯；V0 未完成项交接；确认/假设分离；建立首批卡；补正反馈设计草案。
- 不做：SwiftData 改动、发奖、数值确认、家庭数据迁移或 App UI。
- 验收：独立读者能确定唯一任务、13 条规则、数值仍待确认和下一步；无与用户确认冲突的当前指令；差异检查通过。

## V1-M1-001 冻结 V0 schema 与合成磁盘夹具

- 依赖：V1-D-001。
- 范围：保存八模型 V0 持久化定义的独立基线，防止以后当前模型变更使“旧库测试”偷偷成为新库测试；合成固定日期对象图覆盖历史完成、活动/暂停计时、detached 单日、通知映射、日期覆盖、AppSettings 的 Keychain 引用。
- 不做：新增 V1 字段/奖励模型、改正式容器、读真实数据库或 Keychain 凭据、旧包安装、数值默认。
- 验收：独立 V0 schema 创建磁盘库，旧库跨容器重开后固定 ID、字段、关系、计时、覆盖与 PIN 引用一致；当前 V0 schema 可读取冻结基线生成的库，且不丢对象。两系统专项和完整单测、横屏构建、静态分析及严格格式通过；没有在活跃 SQLite 上删除辅助文件。
- 产物：冻结模型/夹具、测试、基线说明与结果包索引。随机临时目录仅用于隔离路径，不把随机/真实时间当业务测试输入。

## V1-M1-002 兼容迁移与新任务快照

- 依赖：V1-M1-001。
- 范围：版本 schema/迁移计划；分类待设置/全天/自行确认/奖励零/时间可空等已确认默认；旧历史自主 unknown；旧库夹具→新 schema→再次重开测试。
- 不做：自动补奖、设置产品默认数值、宠物或 UI。
- 验收：新建、空旧库、八模型完整旧库和历史/计时/关系/稳定标识保持；迁移幂等、无破坏性回退；双系统全量回归及横屏构建通过。

## V1-M1-003 XP/Coin 账本内核

- 依赖：V1-M1-002。
- 范围：不可变交易、稳定业务幂等键、显式输入奖励、余额与有效 XP 派生；所有输入校验和失败语义。
- 不做：产品默认值、宠物等级阈值、UI 发奖入口。
- 验收：重复业务键不重复写入、收入/消费/冲正区分、余额不足拒绝、失败无半写入、固定数据磁盘重开一致；双系统测试通过。

## V1-M1-004 自行确认与一次性奖励

- 依赖：V1-M1-003。
- 范围：自行确认事务、提醒/奖励快照、自主边界与一次结算；零奖励旧任务仍可完成。
- 验收：提醒前三边界、重复点击/重启、模板修改保护、失败原子性与通知清理；无新默认值；双系统测试通过。

## V1-M1-005 撤销与审计冲正

- 依赖：V1-M1-004。
- 范围：沿用现行撤销入口约束；原记录保留、冲正唯一、余额不足明确拒绝；有效 XP 重算输入。
- 验收：窗口内/外、零奖励、已消费、重复撤销、失败及重开，不删除交易/消费、不允许负余额；双系统测试通过。

## 后续拆卡入口

家长验收状态与提交历史 → 通知/计时衔接 → 编辑器和儿童展示 → 正反馈 UI → 宠物参数确认及消费 → 基础统计。进入各阶段前再拆可在一次会话内完成的小卡；原改造计划顺序仍适用，但不把整个阶段算成一张巨卡。

宠物数值、默认奖励、设备用途、分发和实际家庭观察仍需用户，不能以本卡建立等同确认。模型与奖励内核可先推进显式输入和零奖励兼容。
